Park until an event matching your filter lands or your tick cadence comes due — the GM's wait_for_change, and the primitive an event-woken director uses once per process. Scheduled directors do not call this; their supervisor launches them only when due. Pass `events` (event type names to wake on) and/or `everyTicks` (a pacing heartbeat). If nothing matches it returns on its own after a timeout (~30s) with status "idle". A human GM may re-call while idle; an automated director writes memory and exits so its supervisor can relaunch it fresh. Unlike a character's park this never drives the clock: time passes only while characters play, so on an empty world expect idle heartbeats.

`events` matches BOTH streams: the in-world event log (`victory`, `said`, `rule_error`, any type a rule emits) and the GM audit trail (`world_grew`, `world_regenerated`, `entity_spawned`, `announced`, ...). Threshold triggers are not a parameter — author your own tripwire instead: add_rule a watch rule (`{"phase":"watch","when":{...},"emit":{"type":"my-tripwire","global":true}}`) and wake on `events:["my-tripwire"]`. You program your own senses.

Every return — idle or changed — carries a `pulse` digest (population, deaths, stock trends, chat volume, ticks since the last GM action / decision-worthy event), so an empty wake is still a usable pacing read. Results are cursored: an event is delivered once, never re-delivered, and your own GM actions echo in the audit stream — ignore them. Matched events are compact projections; drill into anything interesting with inspect_world.
